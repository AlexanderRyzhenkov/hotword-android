# Contributing / Участие

## Русский

1. Проверьте существующие Issues, прежде чем создавать новую задачу.
2. Для Pull Request опишите цель, тесты и связанные Issues. Предпочитайте небольшие независимые изменения.
3. Не добавляйте в репозиторий файлы голосовых записей, пользовательские данные, APK, загружаемые модели и ключи подписи.
4. Сохраняйте вызов помощника независимым от конкретного бренда. Любые интеграции с поставщиками должны быть необязательными.
5. Не заявляйте, что ограничения Android на фоновый запуск обойдены, без воспроизводимого теста с указанной версией ОС.
6. При изменении пользовательского поведения обновите обе версии README.

## English

1. Review existing Issues before opening a new one.
2. Keep pull requests focused; describe their purpose, tests, and related Issues.
3. Do not commit voice recordings, personal data, APKs, downloaded language models, or signing keys.
4. Keep assistant invocation vendor-agnostic. Provider-specific integrations must remain optional.
5. Do not claim background-launch restrictions are solved without a reproducible device test and OS version.
6. Update both READMEs when user-facing behavior changes.
